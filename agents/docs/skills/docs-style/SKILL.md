# Documentation Style

## README skeleton
1. One sentence: what this project does
2. Screenshot / sample output (if any)
3. Installation (copy-paste block)
4. The 2-3 most common usage examples
5. Configuration table (option | default | description)
6. Contributing / license

## Writing rules
- Active voice, present tense: "X does Y", not "Y is done by X".
- Paragraphs ≤ 4 lines; use a list for 3+ consecutive items.
- Headings are actions/nouns, not questions: "Installation", not "How do I install?".
- In-code names go in `backticks`; so do file paths.
- In non-English text, use the established local term for a technical term if one exists; otherwise keep the English term - fluency comes first.

## Release note template
- **New:** ...
- **Changed:** ... (breaking changes marked with ⚠)
- **Fixed:** ...
